# Agentic Data Cleaner -- notebook + public MCP server

Finds and fixes problems in tabular data (CSV, TSV, Excel, JSON, Parquet, ...): duplicates, placeholder nulls (`N/A`, `?`),
numbers/dates stored as text, spelling variants, encoding damage, outliers, personal data. Safe fixes apply automatically;
anything that deletes or invents data waits for a human yes. Every run produces the cleaned file, an audit report and a
standalone replay script.

**Live right now, no install needed:** the public server is
`https://dc-mcp-26zy.onrender.com` -- homepage `/`, install guide `/install`, about `/about`.
Connect any MCP client to `https://dc-mcp-26zy.onrender.com/mcp` (Streamable HTTP, no key required) and clean data
from inside Muse, Claude, ChatGPT, Cursor, VS Code, Opencode or Antigravity.

One engine, three ways to use it:

```
datacleaner/engine.py  ──►  agentic_data_cleaner.ipynb   (generated by tools/build_notebook.py -- can't drift)
        │
        └──────────────►  server/  ──►  MCP endpoint  /mcp   (any MCP client, keyless)
                                    └──►  REST API      /v1/...  (OpenAPI at /docs)
```

## 1. Use it hosted (easiest)

Add a remote MCP server in your AI client:

```json
{ "mcpServers": { "agentic-data-cleaner": { "serverUrl": "https://dc-mcp-26zy.onrender.com/mcp" } } }
```

(Antigravity uses `serverUrl`; Claude/Cursor/opencode use `url` -- same value. No `Authorization` header needed;
keyless visitors are isolated per IP and get the free tier.) Then ask your assistant to
*"clean this CSV with the data cleaner"* and paste data, or point it at a file.

Full per-client guide with copy-paste snippets: https://dc-mcp-26zy.onrender.com/install

## 2. Use the notebook locally (no server, no internet)

```bash
git clone https://github.com/iishanmakkar/dc-mcp.git
cd dc-mcp
pip install -r requirements.txt jupyter
jupyter lab agentic_data_cleaner.ipynb     # Run All -- put your file in input/, get results in output/
```

The notebook cleans `input/uncleaned_data.csv` by default -- replace it with your own file and Run All.
Or as a library: `from datacleaner import AgenticDataCleaner; AgenticDataCleaner("data.csv").run(interactive=False)`.
A model is optional (`LLM_*` in `.env`); without one, deterministic rules plan everything.
Nothing leaves your machine: no server, no keys, no uploads.

## 3. Self-host the server

```bash
pip install -r requirements.txt
cp .env.example .env            # then edit: API_KEYS, PUBLIC_BASE_URL, ALLOWED_HOSTS
python -m uvicorn server.app:app --port 8000 --env-file .env   # Windows (uvicorn --env-file loads .env)
curl localhost:8000/healthz     # {"ok":true}
```

(On Linux/macOS: `set -a; . ./.env; set +a` before `uvicorn server.app:app --port 8000`.)
MCP endpoint: `http://localhost:8000/mcp`. REST docs: `/docs`.
With no credentials configured the server **refuses to start** -- set `API_KEYS`, configure OAuth,
or `ALLOW_ANONYMOUS=true` (local development only).

### Tools your assistant sees

| Tool | What it does |
|---|---|
| `clean_dataset` | One call: scan -> apply every safe fix -> export links. Returns `needs_your_decision` for risky items |
| `scan_dataset` | Load a file, list every problem, change nothing. Returns `dataset_id` |
| `get_cleaning_plan` | Proposed fix per problem, with risk and "applies automatically?" |
| `apply_cleaning_plan` | Apply low/medium items; high-risk items only via `approve_ids` (the user's explicit yes) |
| `apply_cleaning_action` | One specific action; risky ones need `confirm=true` |
| `preview_dataset` / `export_dataset` | Look at rows / get time-limited download links (csv, tsv, xlsx, json, jsonl, parquet) |
| `create_upload_url` | One-time URL for files too big to pass inline |
| `delete_dataset` / `list_cleaning_actions` | Delete now / list actions |

Input can be `file_base64`, `csv_text`, a public `file_url` (https only, SSRF-guarded) or an `upload_id`.

## 4. Deploy your own copy

```bash
# Fly.io (fly.toml):  fly launch --no-deploy  ->  fly secrets set API_KEYS=...  ->  fly deploy
# Render   (render.yaml):  push to GitHub -> New + -> Blueprint -> key is auto-generated, check the URL vars
# Vercel   (vercel.json):  static marketing site only (docs/site) -- the Python MCP needs a persistent host
```

Set `PUBLIC_BASE_URL` / `ALLOWED_HOSTS` to your real domain. Serve with a single worker
(datasets live in process memory; see "Scaling" below). Then verify:

```bash
python tools/preflight.py https://your-domain.example YOUR_API_KEY
```

It checks everything a reviewer touches (public pages, auth, MCP handshake, a real clean + download) and exits 0
only when all pass. **Scaling:** run one instance/worker; to go multi-instance, move
`server/store.py` and the meters in `server/quota.py` to Redis/S3.

## Security model (what is actually enforced, and tested)

* Bearer-key and/or OAuth 2.1 JWT auth (`AUTH_MODE=key|oauth|either`); optional keyless public mode isolates
  visitors per hashed IP, and a wrong key is always rejected.
* Each client's datasets are isolated -- "not yours" and "doesn't exist" look identical; per-IP buckets for anonymous users.
* Unguessable dataset/download/upload tokens; datasets, artifacts and upload slots expire (default 1 h, cascade on expiry)
  and can be deleted on demand; public download/upload links are IP rate-limited.
* Only allow-listed formats are parsed (csv/tsv/txt/psv/json/jsonl/xlsx/xlsm/parquet). No pickle, HDF5, SQLite, HTML/XML,
  legacy `.xls`; no server file paths; row/column/size caps; ragged rows rejected before parsing; zip-bomb checks on
  `.xlsx`; Parquet uncompressed-size checked before reading.
* URL fetching: https/443 only, no credentials, every address must be public (DNS resolved once, connection pinned
  to that IP), redirects re-validated, size and time capped.
* The actions are a fixed registry -- no code execution, no user regexes. A model (if you enable one) cannot lower risk, invent
  actions or touch missing columns; and `LLM_ENABLED` is **off** by default with cell values redacted when on.
* Errors return generic messages (stack traces stay in server logs); logs hold ids and counts, never data.
* DNS-rebinding protection on `/mcp` (`ALLOWED_HOSTS`), `nosniff`, `no-store`, strict CSP on all public pages.

## Honest limits (please read)

* **Scheduled cleaning is not built** -- the feature most likely to justify a subscription (see `docs/monetization.md`).
* Long calls: a 200k-row file took ~8 s locally. Confirm the calling platform's tool timeout before advertising that size.
* Legal pages (`/privacy`, `/terms`) describe actual behavior but are not legal advice.
* The Dockerfile is untested (no Docker in the build environment); the app itself was tested via uvicorn + real MCP clients.
